# 最小原型实验室方法论（Phase 3）

## 设计原则

1. **位置与体量**：`.temp/<topic>-lab/`（目录自忽略、Phase 5 交付后可清理、不入库），单文件，<500 行。
2. **纯标准库**：零第三方依赖，`uv run --no-project python <file>.py --selftest` 直跑（无 uv 时 `python3 <file>.py --selftest`）。
3. **验证机制而非模型能力**：材料里的 LLM 角色（solver / refiner / guidance）全部用
   确定性 mock 或脚本化序列替代——原型回答「机制是否自洽」，不回答「模型是否聪明」。
   在文件头声明这一点。
4. **环境确定性**：无随机数、固定 episode 序列——同一命令永远同一日志，实验才可复现。
5. **每个核心机制一个可指认的实现单元**（函数/类），并在笔记里给出行号速查表。

## 场景设计（让机制「演」出来）

- 构造一个玩具域，覆盖 **3 类样本**：正常路径 / 陷阱路径（需要某机制才能通过）/
  边缘路径（需要另一机制才能通过）。样本分数 = 三类成功率的均值，保证「单机制提升」
  与「组合提升」都能在分数上区分。
- 以下以 Procedural Graph 类「提案 → 验证」材料为例（其他材料替换为对应的决策类型）：脚本化的「refiner/提案器」按轮次给出编辑，至少包含——
  1. 一次**正收益编辑**（从失败复盘得出，分数上抬）；
  2. 一次**过拟合编辑**（训练集动机成立、验证集大跌，被门拦下）；
  3. 一次**命中负证据后改提次选**的编辑（演示拒绝记忆改变搜索方向）；
  4. 一次**中性编辑**（只改属性/批注，平局接受）；
  5. 一次**结构非法编辑**（环/死端，校验阶段直接拒、不跑验证）。

## selftest 纪律

- 逐轮 assert 决策类型（accept / reject / accept_tie / reject_structural）与分数。
- 输出人类可读的逐轮决策日志（每轮一行：决策 + 编辑签名 + 分数变化 + 一句话动机）。
- 结尾打印 `SELFTEST PASSED ✔`；全流程 <3 min（toy 域应在秒级）。
- 把最终产物序列化（如 JSON）落盘在 lab 目录内，证明表示层完整。

## 破坏性实验（核心教学创新）

> 目的：证明「每个组件拆掉都有具体的、可复现的坏法」。这是判别工程组合创新的试金石，
> 也是让外行一看就会的实景来源。

方法：

1. **逐一拆核心机制（按实取数，≤5 个），每次只拆一个**，改动控制在一两行（改一个比较符 / 删一个分支 / 跳过一项校验）。
2. 改完**真跑**，逐字记录退化日志——禁止纸面推演代替实测。
3. 意外发现照单全收（实战中「拔掉拒绝记忆」预期只是省预算，实测发现搜索不换方向、
   终态差 0.20——比预期更有讲头）。
4. 每个实验按三件套报告：**改了什么 / 实测观察到什么 / 教训一句话**。
5. 拆后无退化须分析原因并分别处理：冗余设计 → 如实记录；测试覆盖不足 → 按[场景设计](#场景设计让机制演出来)补齐该机制的陷阱 / 边缘样本，重跑完整 selftest 全绿后再拆（补样本不得针对拆后结果调参）。除此之外严禁为制造退化而修改玩具域。

实测范例（Procedural Graph lab）：

| 实验           | 改动            | 实测退化                                                         | 教训                                             |
| -------------- | --------------- | ---------------------------------------------------------------- | ------------------------------------------------ |
| 平局门改严格门 | `>=` → `>`      | 属性级中性改进被永久拒绝                                         | 门挡的应是退化，不是无改进                       |
| 拔掉拒绝记忆   | R3 看不到黑名单 | 重复提案再被拒一次，更好的编辑从未被发现，终态 0.80 vs 正常 1.00 | 负证据的价值是强迫搜索换方向                     |
| 关掉环校验     | 跳过环检测      | 垃圾环边以平局混入图                                             | 分数门拦不住「无害但无用」，结构校验拦的正是这类 |

## 预测题答案键实跑

- 为 [lecture-format §4.2](lecture-format.md#42-外行四测题型与命题准则-layperson-four-tests) 看会项预测题的每个新输入各实跑一次原型，把输出逐字回填为该题答案键，标注「实际运行日志」；日志只存 lab 目录、不回灌精读笔记，以免题面新输入在成稿中命中；新输入只改场景数据或参数，不为凑出某个答案而改机制逻辑。
- 回填后按 2c 登记口径重算答案键 sha256，追加记入进度清单（旧值保留），此后方可派发该题。
- 按[分流矩阵](../SKILL.md#输入分流与裁剪矩阵)裁剪、没有原型可跑时，答案键按 lecture-format §4.2 取材料明文，都没有则改出走查题，不以纸面推演充当。

## 原型 → 讲授回灌

- 把实测日志与关键中间产物（如 guidance 的完整输入提示、翻译输出）**穿插进精读笔记**
  的对应机制小节，标注「实际运行日志」——这是「画面感」的来源。
- **实测边界**：原型只证明机制逻辑按描述运作；除非按材料的设置复现，否则不把原型数字写成复现了材料的结果，数字与材料不同也不据此断言材料有误。
- 破坏性实验独立成「动手实验室」小节：运行方式 + 机制→代码行号速查 + 三件套实录。
- 在自治流水线中由 Agent 自主跑通并完整记录退化数据回灌笔记，同时在交付物中提示用户亲手重跑与再拆：`cd .temp/<topic>-lab && uv run --no-project python <file>.py --selftest`（无 uv 时 `python3 <file>.py --selftest`）。

## 卫生

- 原型写在 `.temp/`，仓库根目录不留产物（若 selftest 按相对路径写文件，注意 cwd）；lab 目录首次创建即写入内容仅为 `*` 的 `.gitignore`，不依赖项目是否忽略 `.temp/`。
- 笔记入库时声明原型位于 `.temp/`、随清理消失、可用笔记中的日志复刻。
