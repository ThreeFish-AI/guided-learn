# 讲授与沉淀模板（Phase 1–2 · 4）

Phase 1–2 的解剖、规律、争议与内省考评在后台自治推进，并作为核心资产编入 Phase 4 的沉淀文件；Phase 4 的两份沉淀文件按本文末尾的文档模板落盘入库。

## 1. 全貌讲授结构（Phase 1）

按以下骨架输出，开头不加寒暄，必须显式回应全貌三大核心问题：

```markdown
## 0. 一句话本质与贯穿总类比
## 1. 最重要的几个部分（分层矩阵）
   | 层级 | 部分 | 回答的问题 | 性质 |  ← 表格解剖
   Tier 1 地基与核心机制（精读） / Tier 2 证据链群（评判真伪） / Tier 3 领域地图坐标
## 2. 核心关系与因果脉络链（它们之间是什么关系）
   观察 → 归因 → 设计规格 → 机制解构 → 证据闭环（文字流程图）
## 3. 基础层 vs 学习焦点排序（哪些是基础，哪些最值得关注和学习）
   (a) 前置基础与门槛要求（在此融入 Phase 0 学徒自测与补课建议）
   (b) 最值得关注与学习的 N 个焦点（按价值排序 + 遴选理由）
   (c) 批判性边界（5 条材料未证明的事，防范单方面叙事过度说服）
```

### 1.1 类比设计规范（认知隐喻四硬律）

1. **单一世界观贯穿（Single Theater Anchor）**：全篇必须确立唯一的宏观物理剧场（如：师傅带徒弟 / 菜谱 vs 词典 / 导航 / 数字化大厦带教），所有局部机制必须是该剧场内的子角色、工具或协作流程，**严禁跨段落剧场跳跃**。
2. **单射映射恒定（Bijective Consistency）**：**同一个技术概念在全文各段落必须始终对应同一个比喻角色**，各段落仅按机制重点展示其不同的职责切面，**严禁一物多喻**（避免读者在异构角色间频繁切换造成严重认知摩擦）。
3. **贴切不硬比（High Structural Fidelity）**：类比必须与技术机制在深层因果关系上自然同构、符合生活常识，**严禁牵强附会的“硬比喻”**；若某一纯数学或底层算法缺乏贴切的生活隐喻，宁可直接进入清晰的术语与图解，绝不削足适履。
4. **极简即止（Graceful Fallback）**：类比只是唤醒读者第一直觉的“点火器”，**1–3 句讲完切入核心**；机制展开与细节证明必须迅速回到严谨的工程术语与实测代码/数据，绝不用类比硬凑机制细节。
   - *典范示例（导航世界观）*：总类比选「导航」，局部机制映射为「GPS 定位 ↔ Match、只看前方两路口 ↔ 2-hop 邻域、副驾导航员 ↔ guidance LLM、方向盘在你手里 ↔ 软注入」——世界观统一且四个组成部分单射无缺。

### 1.2 因果链示例（Procedural Graph 实战）

```
观察：轨迹越长 agent 越失控（丢目标/乱序/重复）
  ↓ 归因
程序性一致性的责任被错误压在自由生成上
  ↓ 设计规格（四要求，全文总纲）
结构化 × 推理自由 × 响应进度 × 经验改进
  ↓ 机制
表示层（三元组+属性）→ 在线消费（定位+邻域+生成式软指导）
                     ↕ 两相解耦
                      离线进化（变异→验证门→拒绝记忆）
  ↓ 证据闭环
广度（N 基准 × M 模型）+ 深度（逐轮案例）+ 反直觉（从零进化 ≥ 专家）+ 设计自证（消融）
```

## 2. 领域规律条目格式（Phase 2a）

```
## 规律 N：<名称>（英文锚点）
**最简解释**：一句话，外行能懂。
**理论锚点**：IEEE 引用 1–3 条。
**解决什么问题**：没有它会坏在哪。
**演示**：用一手材料的实证数字现场演示 + 反面演示（它被违反时的实测代价）。
**类比**：一句话。
```

条目完成后声明正交分解：「N 条规律恰好覆盖 X / Y / Z 维度」——分解本身就是领域地图。

## 3. 争议条目格式（Phase 2b）

```
## 争议 N：<标题>——一句话点破张力
**通俗版**：承接统一世界观的生活化场景讲两派分歧（如：手册 vs 导师 / 真学习 vs 背题 / 小抄 vs 肌肉）。
**分歧为什么产生**：两派看到不同的失败模式（各自取样不同 → 都对）；
  指出分歧本质（如：连续谱选址问题 / 验证信号信度 / 成本结构经济学）。
**难以克服吗**：分层——资源问题 / 工程问题 / 本质难题；只对冲不可消除的要说死。
```

## 4. 严师费曼考评与学徒对抗闭环规约（Phase 2c）

本阶段通过 **Mentor Agent（严格导师）** 与 **Learner Subagent（求知学徒）** 的内部高烈度攻防对抗，完成对一手材料机制的无死角检验。全程自治推进，免除用户人工答题负担，对抗全集完整沉淀为知识资产。

### 4.1 资料研究范围界定规范 (Research Scope Specification)
在出题考评前，严格的老师必须先系统解剖本批材料的「研究边界」：
- **目标任务与定义域**：本批材料研究的核心问题、输入输出与架构假设是什么？
- **成立工况与最佳适用区间**：机制在何种场景、假设前提或数据分布下才能发挥最大收益？
- **明确边界与非目标（Out-of-Scope）**：资料明确**没有解决、不适用、或不能外推**的范畴（如：仅在单智能体确定性环境有效，未研究分布式并发容错；防范把局部机制误认为万能银弹）。

### 4.2 费曼三维考评题型库与出题准则 (Feynman Assessment Protocol)
老师出具 3 道深度考核题，必须覆盖以下三个正交维度：
1. **白话机制转述题（外行听得懂）**：
   - 考法：要求借用前文统一世界观剧场或生活常识，将核心机制解释给完全不懂该技术的人听。
   - 硬禁令：严禁直接照搬专业术语与论文原词；凡出现术语必须用白话自洽解释，否则判定为未过。
2. **因果与最近邻本质差异题（知其所以然）**：
   - 考法：将本方案与业界主流 baseline 或最近邻方案（如经典方法）直接对标，要求说清“旧方案在因果链哪一步死掉，新机制是如何对症下药的”。
3. **极限场景与退化预测题（知其边界）**：
   - 考法：设计一个未在材料中直接提及的新场景、极端负载或边缘条件，要求推演机制的运行链路，并预测“它在何处会最先退化或崩溃，为什么”。

### 4.3 求知学徒代管作答准则 (Learner Subagent Protocol)
内置的 Learner Subagent 代表求知者与工程实战视角独立应试：
- **拒绝八股复读**：严禁机械摘抄论文结论，必须基于第一性原理展开因果推演。
- **白话通透表达**：强制代入贯穿总类比或日常生活常识解说机制，暴露真实的推演逻辑。
- **极限勇敢推演**：针对退化预测题，必须主动指认系统最脆弱的瓶颈，推演首个崩溃点。

### 4.4 学生薄弱点诊断量规与归因矩阵 (Weakness Diagnostic Rubric)
老师在审阅学徒作答时，必须出具《薄弱点诊断》，精确归因至以下四类认知缺陷之一：
| 缺陷类型 | 表现特征 | 归因与根源 |
| :--- | :--- | :--- |
| **行话复读 (Parroting)** | 堆砌生僻技术词汇、背诵公式与架构名，但无法用白话解释因果 | 机械记忆，未建立物理直觉与生活心智映射 |
| **因果断裂 (Causal Gap)** | 知道组件 A 连着组件 B，但说不清为什么必须有组件 A、拔掉会引发何种崩溃 | 知其然不知其所以然，缺乏机制推演能力 |
| **边界模糊 (Boundary Confusion)** | 忽视成立前提与研究范围，将机制误当作任何场景都适用的银弹 | 缺乏批判性思维与工程约束意识 |
| **方案混淆 (Neighbor Conflation)** | 说不清与 baseline 或替代方案的本质差异，把通用特性当成本机制特有创新 | 未看透机制的真正增量所在 |

### 4.5 针对薄弱点的充分教授三板斧 (Targeted Deep Remediation)
严师坚决不复读讲义车轱辘话，必须针对诊断出的具体薄弱点实施三板斧深度补课：
1. **世界观微类比点醒**：在全篇统一世界观剧场中引入具体的微冲突场景，直观展现问题本质。
2. **第一性因果溯源**：从“如果系统里没有这个设计”开始，一步步逆向推导其不可或缺性。
3. **破坏性失败反例**：给出真实的实测崩溃案例或极限反例，看到违反该机制时的实测代价。

### 4.6 同构变式复考与出闸门禁 (Isomorphic Re-test Protocol)
- **严禁复考原题**：复考原题仅能验证短期记忆，无法验证真实理解。
- **同构变式设计**：保持底层机制与考核目标严格一致，但**完全更换业务场景、输入边界或干扰因素**。
- **出闸判定**：Learner Subagent 在变式题中回答因果清晰、边界明确、表达通俗者，方可判定门禁全绿通过，正式结业并自动放行进入 Phase 3 原型实验与破坏性验证。
