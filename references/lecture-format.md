## 1. 全貌讲授结构（Phase 1）

按以下骨架写入 lab 工作记录（Phase 4 起草的输入），开头不加寒暄，必须显式回应全貌三大核心问题：

```markdown
## 0. 一句话本质与白话主线
   白话主线（3–5 句直讲：要解决的问题 → 为什么难 → 核心思路 → 怎么验证）+ 难点概念清单（各一句难点）；遴选纪要与《类比登记表》另存 `lab/analogy.md`（见 §1.2；零类比直讲时为空表 + 一行零类比声明，措辞不限），不进精读笔记
## 1. 最重要的几个部分（分层矩阵）
   | 层级 | 部分 | 回答的问题 | 性质 |  ← 表格解剖
   Tier 1 地基与核心机制（精读） / Tier 2 证据链群（评判真伪） / Tier 3 领域地图坐标
## 2. 核心关系与因果脉络链（它们之间是什么关系）
   观察 → 归因 → 设计规格 → 机制解构 → 证据闭环（文字流程图）
## 3. 基础层 vs 学习焦点排序（哪些是基础，哪些最值得关注和学习）
   (a) 前置概念清单（Phase 0 提炼，≤3 项；成稿中在读者首次需要处就地讲清）
   (b) 最值得关注与学习的 N 个焦点（按价值排序 + 遴选理由）
   (c) 批判性边界（材料没有证明的事，按实取数 ≤5 条，防范单方面叙事过度说服）
```

### 1.1 类比使用规约（四硬律）

叙事手法从属于理解：无论白话、类比、图解还是反例，都只是手段，唯一目的是让外行听懂目标对象本体。主线默认白话直讲——第一拍以最快让外行听懂为准自由取材（痛点直陈、具体数字、反例钩子、图示或实景先行皆可，不设固定开场句式），类比只许作为白话内部的点缀，**严禁升格为贯穿全篇的剧场、世界观或品牌**；零类比直讲（全篇不用任何类比）是合法且常见的形态，不得为凑类比而造类比。选用局部类比恪守四硬律：

1. **难点准入（Hard-Concept Gate）**：只为「白话直讲后直觉最难唤醒」的概念引入类比（难点概念于 §1.2 按难度分级识别：论文级 ≤5 个、轻量 ≤2 个，0 个即零类比直讲），其余概念一律白话直讲；**严禁给白话能讲清的概念强配类比**，更严禁为覆盖全篇而扩张映射义务。
2. **一物一喻与标题禁令（Concept-Level Single Mapping）**：**同一概念在全文各处必须沿用同一类比**、仅展示其不同职责切面，**严禁一物多喻**；**同一喻体不得承载两个不同概念**（登记时须扫一遍既有条目防撞）；章节标题、图表命名与目录等导航要素**严禁使用本笔记自引入的类比域词汇**（目标域固有术语、其行业惯用隐喻如 Guardrails/垃圾回收、材料为机制自命名的隐喻词如 Tree of Thoughts 均视作目标域术语，不在此列）——标题必须承载目标域信息，不得让读者先学一套私人语言才能定位内容。
3. **贴切不硬比（High Structural Fidelity）**：类比必须与机制在深层因果关系上自然同构、符合生活常识，**严禁牵强附会的“硬比喻”**，严禁发明类比域不存在的合成道具——一旦需要「手册本身就是计算器」式混血道具才能对上机制，即证明此处类比无解释力，必须放弃类比改直讲；无贴切生活隐喻的概念直接进入术语直讲，绝不削足适履。**一票否决四判据——① 仅表面相似、因果不同构（硬比）；② 外行须先具备专业知识才懂；③ 必然诱发材料不成立的错误推论；④ 需发明合成道具——全量适用于任何类比句**：无论长短、无论用于难点概念、开篇引子还是行文点缀，命中任一即弃。
4. **极简即止与失配拦截（Graceful Fallback & Misfit Guard）**：类比只是唤醒读者第一直觉的“点火器”，**1–3 句讲完切入机制**；机制展开必须迅速回到严谨的工程术语与实测代码/数据，绝不用类比硬凑机制细节、更绝不用类比域数字换皮机制参数；每个入选类比必须在《类比登记表》写明失配边界，**仅当失配可能诱发与材料相悖的推论时**才在正文机制节内一句拦截（如「这个比方到此为止：它并不能……」），其余失配只记登记表、不进正文。

四硬律之外的三条执行红线：

- **裸讲测试**：抽 2–3 个核心机制（可用不足时按实计）不用任何类比、纯白话讲清（绑定 Phase 1 讲解片段复述与 §4.2 读懂项，见 §1.2 第 6 步）；讲不清即证明该处没讲透、类比在替机制兜底，必须回炉直讲——**类比不得成为理解的必要媒介**。
- **证据链隔离**：类比域内的事实（含材料自带隐喻域的历史与行业惯例）一律不得作为目标域结论的论据，只能作解释装置（铁律 3 循证讲授不受类比影响）。
- **开篇引子例外**：材料自带天然强隐喻时，可用一段（≤5 句）作开篇引子，并须明示「此为材料自身的说法」；引子不得贯穿全篇、不得进入标题、不承担映射义务；遴选上仅过硬律 3 一票否决、免外行抽检（硬律 2 喻体防撞与「证据链隔离」红线对引子同样适用）；零类比直讲（登记表为空）时不使用引子。

### 1.2 难点概念遴选协议（脑暴-快筛）

随手拈来的类比会污染概念引入点并被下游消费（Phase 2a 规律条目、2c 题面、Phase 4 各节点缀均可能引用），故**严禁不经遴选直接落笔**。遴选对象是「逐概念局部类比」：先识别难点，再逐概念脑暴-快筛（先发散后收敛的两段式择优 [5]），登记入表；零合格候选即该概念直讲，无全场回退负担。**执行时序**：先在内部完成分层矩阵、因果链与核心争议预判草稿作为评估基准，再启动遴选；呈现仍以 §0 开篇。**难度分级**：论文与长文档按实识别难点概念、至多 5 个（0 即零类比直讲），每概念候选 5–10 个；视频与代码库按论文与长文档口径执行（输入分流不裁剪其 Phase 1）；轻量材料（博客短文等）至多 2 个（0 个即零类比直讲）、免执行论文级 5–10 个候选脑暴。**不随[输入分流裁剪](../SKILL.md#输入分流与裁剪矩阵)降级的硬底线**：一票否决快筛对任何类比句一律适用，外行抽检对登记条目一律适用（抽样口径见第 5 步）。

1. **难点识别（Gate）**：解剖完成后按导语难度分级列出「白话直讲后直觉最难唤醒」的概念（论文级 ≤5 个、轻量 ≤2 个，宁缺毋凑；判据：讲完术语与因果后，由 Learner 代演的外行预测该机制在新场景下的行为，预测错即为难点；典型如反直觉设计决策、隐性时序约束、多角色协作），各附一句难点（读者卡在哪）。零难点即零类比直讲：仍按第 4 步在 `lab/analogy.md` 留空表与一行零类比声明（措辞不限），再直接做第 6 步裸讲终检。
2. **脑暴发散（Diverge）**：论文/长文档的每个难点概念列举 **5–10 个**候选，记为「类比 + 一句话映射（X ↔ 机制要点）」；候选至少覆盖 **3 个生活域**（不同概念可用不同域），防止首个念头锁死 [4]；发散期只增不删、不打分，候选列满前不得定选，首个直觉候选不享有任何先验加权 [1]。轻量材料免执行这组 5–10 个候选脑暴；若确需选用局部类比，最多列 1–2 个候选，仍须逐一通过第 3 步快筛，不得跳过硬底线。
3. **快筛收敛（Converge）**：逐候选过 §1.1 硬律 3 的一票否决四判据，命中任一即淘汰；幸存者按「贴切优先 [2] → 生动 [3]」排序取首选与 1 个次选（同概念回退用；幸存者仅一个时无次选，处置见第 5 步），**每项须附一句映射证据**；候选全灭即该概念直讲。
4. **登记与《类比登记表》（全篇类比单一事实源）**：`| 概念 | 类比（1–3 句） | 失配边界 | 首登章节 |`，只登入选类比与失配边界——不设剧场、不编排故事线、不承担覆盖义务；登记表存 `lab/analogy.md`，不进精读笔记。**写时消费纪律**：正文任何类比句必须对应登记表既有条目（§1.1 开篇引子除外：不登记、不承担映射义务，但须明示「此为材料自身的说法」）；新增类比必须先登记（含失配边界与防撞检查）再使用；同一概念必须沿用同一类比（硬律 2）。零类比直讲时仍在 `lab/analogy.md` 产出空表 + 一行零类比声明（措辞不限）+ 裸讲终检记录。
5. **外行瞬时理解抽检**：抽登记表全部条目（≤3 条时全抽；>3 条时抽 3 条；空表免检），由 Learner Subagent 扮演完全外行逐条判断：「听到这个类比，你能秒懂这个概念吗？（1–5 分）」。任何一条 ≤2 分即触发：① 优先在该条「类比」栏补一层更接地气的解释（不换类比，正文引用仍守硬律 4 的 1–3 句即止）；② 复评仍 ≤2 分则弃用该类比、启用次选重跑登记（正文引用旧类比的句子同步改写为新类比或直讲；无次选可用——幸存者仅一个或轻量单候选——时不补选、径直按「次选也不行」处置）；次选也不行即该概念转直讲，并回写登记表（删除该概念条目、同步清除正文对应类比句）——凡弃用或更换类比，一律同步登记表与正文引用；回退天然有界，严禁无限回退。抽检结果记入遴选纪要。该分数只作类比快筛，不作外行可懂证据（可懂与否以 §4 外行四测的答题表现为准）。
6. **裸讲终检与失配暴露**：挂在 Phase 1 讲解片段复述上——抽 2–3 个核心机制（可用不足时按实计；登记表非空时其中至少 1 个须为已登记类比的概念），把这几段讲解片段与白话主线交给全新 Learner（照 §4.3 作答），题面要求不借任何类比、纯白话复述机制并答 ≤2 道因果题；Mentor 先写出该片段与因果题的期望要点，再按 §4.4 逐要点判分并归因到片段文本（免闭卷对照），讲不清即回炉该片段的直讲文本、由全新 Learner 复测（至多 2 轮，仍不过记为 lab 风险，Phase 5 读懂项重点抽测该机制），必要时弃用该概念类比降低依赖（同样须回写登记表与正文引用），严禁以「再讲一遍类比」代替讲透机制；另对已登记类比的概念，新派一个输入仅含「概念名 + 登记类比」的 Learner（不得携带讲义或复述上下文），令其只凭类比推断该机制的一个行为、再与材料对照，推断被带偏即失配暴露，按第 5 步同序处置——启用次选重跑登记与抽检（无次选可用时径直转直讲），次选也不行即该概念转直讲并回写登记表（删除条目、清除正文类比句）。

**遴选纪要（存 `lab/analogy.md`，不进精读笔记）**：难点概念清单（各一句难点）；候选池「分域一行式」罗列（名称以顿号分隔，仅作索引、不展开）；在「逐概念候选与快筛明细」中逐概念保留候选、映射证据、否决原因或入选/次选结论；否决项计数 + 代表例；入选条目、外行抽检得分与处置；裸讲终检结论；使用开篇引子时另附其一句一票否决与喻体防撞结论。零类比路径的退化口径：零难点时纪要仅需「难点概念清单（空）+ 一行零类比声明 + 裸讲终检结论」；候选全灭时保留候选池与否决计数，入选条目与外行抽检各项免填。

### 1.3 因果链示例（Procedural Graph 实战）

```
观察：轨迹越长 agent 越失控（丢目标/乱序/重复）
  ↓ 归因
程序性一致性的责任被错误压在自由生成上
  ↓ 设计规格（四要求，全文总纲）
结构化 × 推理自由 × 响应进度 × 经验改进
  ↓ 机制
表示层（三元组+属性）→ 在线消费（定位+邻域+生成式软指导）
                     ↕ 两相解耦
                      离线进化（变异→验证门→拒绝记忆）
  ↓ 证据闭环
广度（N 基准 × M 模型）+ 深度（逐轮案例）+ 反直觉（从零进化 ≥ 专家）+ 设计自证（消融）
```

## 2. 领域规律条目格式（Phase 2a）

```
## 规律 N：<名称>（英文锚点）
**最简解释**：一句话，外行能懂（难点概念可嵌 1 句已登记类比）。
**理论锚点**：IEEE 引用 1–3 条。
**解决什么问题**：没有它会坏在哪。
**演示**：用一手材料的实证数字现场演示 + 反面演示（它被违反时的实测代价）。
```

规律按实取数、至多 5 条，宁缺毋凑：每维一条，找不到真规律的维度不写。条目完成后说明各条分别管哪一维、合起来覆盖什么（措辞不限）——分解本身就是领域地图。

## 3. 争议条目格式（Phase 2b）

```
## 争议 N：<标题>——一句话点破张力
**通俗版**：白话直陈两派各自看到什么、要什么（直讲分歧本体，不设统一剧场；两派立场原文须译成人话）。
**分歧为什么产生**：两派看到不同的失败模式（各自取样不同 → 都对）；
  指出分歧本质（如：连续谱选址问题 / 验证信号信度 / 成本结构经济学）。
**难以克服吗**：分层——资源问题 / 工程问题 / 本质难题；只对冲不可消除的要说死。
```

争议按实取数、0–3 个，只收材料或补读信源中真实存在的分歧；没有真实分歧时写一句说明，不造伪争议。某派立场只由材料作者转述、缺该派自己的一手表述时，开 T4 缺口单补读（见 [source-reading §4](source-reading.md#4-何时补读)）。

## 4. 研究范围与外行四测

本章是 Phase 2c 命题与 Phase 5 验收的判据。外行四测测的是文档而不是读者：Learner 作为外行读者代理只拿文档作答，判据只看答题表现、不看文档用了哪种叙事手法（铁律 8）。Mentor 在 2c 界定研究范围、命题并写答案键；Phase 5 按 [final-polish §5.2](final-polish.md#52-外行四测施测) 施测，按本章判分、修文档与复测，出闸见 [final-polish §5.3](final-polish.md#53-出闸判定)。全程自治推进，免除用户人工答题负担（用户明确要求本人受考时由用户作答，见 [SKILL.md 边界](../SKILL.md#边界与触发契约)）。LLM 代理比真人更容易答对 [12]，所以代理通过只是必要条件、代理失败才是强信号；交付时如实说明验收由 LLM 代理完成，措辞不限。

### 4.1 资料研究范围界定规范 (Research Scope Specification)
在命题前，Mentor 必须先系统解剖材料与已登记补读信源的「研究边界」，结果写入成稿「适用边界」章（§5）：
- **目标任务与定义域**：本批材料研究的核心问题、输入输出与架构假设是什么？
- **成立工况与最佳适用区间**：机制在何种场景、假设前提或数据分布下才能发挥最大收益？
- **明确边界与非目标（Out-of-Scope）**：资料明确**没有解决、不适用、或不能外推**的范畴（如：仅在单智能体确定性环境有效，未研究分布式并发容错；防范把局部机制误认为万能银弹）。

### 4.2 外行四测题型与命题准则 (Layperson Four Tests)
四测把「一读就懂、一看就会、一听便知、一学就通」落成四项可观测的答题表现：说得出不等于做得出 [6]，记得住不等于用得上 [7]，四项不能互相替代，所以分开测。题库合计 ≤10 题，每项至少 1 题：

| 测项 | 可观测能力 | 题式（上限） |
| :--- | :--- | :--- |
| 读懂 | 用自己的话讲回主线，答出主线上的「为什么」 | teach-back 复述 1 + 因果题 ≤2 |
| 看会 | 照着文档把一个没见过的输入走完，或预测改动后的结果 | show-me 走查 1 + 预测 ≤1 |
| 听知 | 只按顺序听一遍、看不到图表也不能回看，仍能复述并做跨段推理 | 线性听稿复述 1 + 跨段推理 ≤1 |
| 学通 | 把机制用到文档没讲过的新场景，并认出不该用的场景 | 近迁移 ≤2 + 边界 1 |

- **读懂**：复述题面为「把这篇文章讲给没读过它的朋友听：要解决什么、为什么难、怎么解决、怎么知道有效，不超过 5 句」，并写明不借任何类比、直讲机制本身（§1.1 裸讲测试的落点；举目标域内的实例不算类比）；答案键中的主线命题＝一句话定位 + 白话主线逐句。因果题取自白话主线与各章章旨的因果链（如「为什么非要有 X」「没有 X 会怎样」）。
- **看会**：走查题给一个研究范围内、成稿里没出现过的具体输入，要求逐步走完机制并给出结果；预测题改一个参数或拿掉一个组件，问结果往哪变、为什么。预测题答案键依次取 Phase 3 用该输入实跑的输出（标「实际运行日志」）、分流裁剪无原型时的材料明文；两者都没有就不出预测题，改出第二道走查题，不以 Mentor 的纸面推演充当答案键（铁律 3）。
- **听知**：施测输入是去掉代码、表格与图片的听稿，按顺序听、带记忆瓶颈——后半段的代理看不到前半段原文，只凭前半段写下的记忆笔记接着听（听稿生成、切分与派发见 final-polish §5.2）。跨段推理题须把前后两段连起来才能答：只听不看时，最容易丢的正是段间推理 [11]。
- **学通**：近迁移题保持机制的深层结构，业务场景与表层细节全部换掉，问新场景里怎么运作、或最先在哪一步出问题 [8][9]；边界题落在 §4.1 的 Out-of-Scope 或「材料没有证明的事」之一，期望答案是「按这份文档不能下这个结论 / 不适用」并给出理由。

**原费曼三维的去向**：白话机制转述 → 读懂复述；因果与最近邻本质差异 → 读懂因果题或学通迁移题（如「换成旧办法会在哪一步坏」）；极限场景与退化预测 → 看会预测题或学通边界题。

**命题准则**：
- 每道非复述题另备 2 道同构变式（底层机制与考点不变，完全更换业务场景、输入边界或干扰因素），供先验可答换题与复测使用；备题用尽时补写的变式记入 `four-tests.md` 的补写节（答案键节不动），同样先写答案键、另行登记补写节的 sha256 再派发。
- 出题偏向本材料特有的设计取舍、实测数字与限制：名著主题上的通用问题，代理不看文档也能答对，没有诊断力 [10]。
- 题面中的新输入与新场景关键词，在 Phase 5 派发前 `command grep -F` 成稿须不命中，命中即换备题，防止代理查表作答。
- 用户自测题（§5）与四测题不重用。
- 用户本人受考时，用户作答免 §4.3 的摘引要求与闭卷对照，Mentor 仍按答案键判分；答不上即按 §4.4–§4.6 修文档、换变式复测。

**答案键**：写入 `lab/four-tests.md` 的答案键节，格式 `| 题号 | 期望要点（逐条、可二值判定） | 材料出处或实际运行日志 |`，备题同样各有答案键；需实跑的看会项要点在 2c 先标「待 Phase 3 实跑」，由 Phase 3 按 [prototype-lab](prototype-lab.md) 实跑后逐字填入。2c 结束时把答案键节的 sha256 记入 `progress.md`，Phase 3 填入实跑结果后重算、追加登记一次，此后不再改动：逐题作答与判定追加在 `four-tests.md` 的后续各节，补记要点与成稿锚点写入 polish-log。Phase 5 派发前预检：逐条期望要点在成稿中找锚点，找不到即文档缺内容，先按 §4.5 修文档再派发。

### 4.3 外行读者代理作答准则 (Learner Subagent Protocol)
外行读者代理就是全新派发的 Learner，不另设角色；压住它先验知识的是结构约束，不是人设描写（画像提示几乎不起作用 [12]）：
- **认知状态画像**：能用的只有日常生活经验与初中程度的数学、语文常识；本材料所在领域、编程与高等数学一律视为不懂；文档里没解释过的词一律当作没听过。
- **输入**：只有文档（开卷稿即成稿去折叠版、听稿或 Phase 1 讲解片段）、题面与下列固定作答准则；不给草稿、原材料、答案键、本规约、前几轮作答与 Mentor 的任何解释。每轮一律全新派发，施测分组与派发顺序以 final-polish §5.2 为准（§1.2 第 5、6 步的类比抽检与失配探针按该节另定输入）。

固定作答准则（原文照发）：
1. 只按这份文档的说法回答，不用你自己知道的其他知识。
2. 每个回答后附依据：`§锚点 + 逐字摘引（≤40 字）`。
3. 文档没讲清就回答「文档没讲清：缺〈什么〉」——这是合格且有价值的回答，瞎猜比说没讲清更糟。
4. 不使用文档里没出现过的术语和英文词。
5. 不要评价自己懂没懂。

### 4.4 判分与文档缺陷归因 (Document Defect Rubric)
Mentor 对照答案键逐要点判 0/1，只认代理明确写出的内容，不替代理补全推理；不问「懂了吗」、不让代理打分——是非式确认不算 teach-back [6]。代理给出答案键之外、但与成稿和材料都一致的答案，可判该要点通过并在 polish-log 补记（答案键节不改）。

开卷之前，先对全部非复述题的正题与备题做一次闭卷对照：同画像、同题面、不给文档的全新代理（派发见 final-polish §5.2）；闭卷与开卷之差才是文档本身的贡献 [10][12]。逐题判定：

| 判定 | 条件 | 处置 |
| :--- | :--- | :--- |
| **先验可答** | 闭卷就答对 | 这道题对代理没有诊断力，不是文档缺陷：换上闭卷未答对的备题；备题也都先验可答时，可补写一道更依赖本材料特有内容的同构题再闭卷一次（为换题而补写新题并加做闭卷，全程至多 1 次）；仍先验可答则只作参考、不计入出闸 |
| **通过** | 开卷答案覆盖答案键全部要点；摘引全部 `command grep -F` 命中所给文档，且足以推出答案；无文档外术语 | 计入出闸 |
| **先验泄漏** | 开卷答对了，但摘引撑不起答案，答案靠的是文档外知识 | 判不通过，多归因为「术语未释」或「前置缺失」 |
| **不通过** | 答错、答不全、回答「文档没讲清」，或用了文档外术语 | 按下文归因，按 §4.5 修文档 |

某项全部先验可答时该项记「无诊断力」（处置见 final-polish §5.3）。**照读**：复述句与成稿某句逐字相同（整句 `command grep -F` 命中）即为照读，不计入主线命题覆盖。**文档外术语**：回答里的拉丁字母词与反引号术语逐个 `command grep -F` 所给文档，找不到即是。

各测项的通过条件：
- **读懂**：复述覆盖全部主线命题（照读句不计），与成稿或材料矛盾的陈述为 0，因果题全部通过。
- **看会**：结果正确、每一步都有文档依据；任何一步报告「文档没说这一步怎么做」即不通过，并定位到这一步。
- **听知**：「听到了但不知道指什么」清单为空，复述覆盖听稿范围内的主线命题，跨段推理题通过。
- **学通**：各题全部通过；边界题给出肯定结论（把机制当万能）即不通过。

**定位与归因**：以代理给的依据锚点定位；代理给不出依据时，以答案键要点在成稿中的锚点为准，落到具体段落。失败一律归因到文档、不归因到读者，归入以下八类之一：

| 缺陷类型 | 答题中的表现 | 承接原缺陷 |
| :--- | :--- | :--- |
| **术语未释** | 照搬或回避术语、用文档外术语，或以类比复述代替机制直讲 | 行话复读 (Parroting) |
| **前置缺失** | 卡在文档默认读者已懂、却没讲过的概念上 | — |
| **因果缺环** | 知道组件 A 连着组件 B，说不清为什么必须有 A、拔掉会引发何种崩溃 | 因果断裂 (Causal Gap) |
| **最近邻差异缺失** | 说不清与 baseline 或替代方案的本质差异，把通用特性当成本机制特有创新 | 方案混淆 (Neighbor Conflation) |
| **只有抽象** | 只有规则没有实例，或步骤有缺口，照着走不完一个新输入 | — |
| **视觉依赖或指代悬空** | 结论只在图表里；听稿中「如图」「它」「上述」指不清 | — |
| **边界不在场** | 把机制当万能，边界没写在读者读机制时看得到的位置 | 边界模糊 (Boundary Confusion) |
| **关键解释埋在折叠块** | 答题所需的解释只在 `<details>` 里，去折叠版读不到 | — |

### 4.5 修文档三板斧 (Targeted Document Repair)
teach-back 检查的是讲的人讲得好不好，不是在考听的人 [6]：不通过即修文档本身，改在读者第一次需要它的正文位置。按归因选用三板斧：
1. **具象实例**（只有抽象）：补一个取自材料或实际运行日志的完整实例（worked example），先具体、再逐步抽掉细节说出一般规律 [8][9]；可用已登记类比点缀，不要求剧场。
2. **补因果一环**（因果缺环、最近邻差异缺失）：从「如果系统里没有这个设计」开始，补出缺失的那一环，必要时点明旧方案在哪一步坏。
3. **破坏性反例**（边界不在场）：引用实测退化或材料里的失败案例，把边界写在读者读机制时看得到的位置。

其余缺陷就地处理：术语未释与前置缺失在该概念正式讲解前一句话讲清，不甩到附录；视觉依赖用一句话在正文说出图表结论；埋在折叠块的关键解释移回正文。**修法优先级**：改写重排 → 就地补一句 → 补完整例子，防止越修越长、主线被稀释。

**禁止旁路补课**（任一命中即视为未修）：
- 不改题面与作答准则，不在其中补充解释；
- 不给代理追加提示后重问；
- 不只在附录、词汇表、FAQ 或折叠块里补而正文不改；
- 修复句不得逐字包含题面里的新输入或新场景（防应试化改文）。

**外行补阙登记**：为过四测新增的解释性文字一律登记为外行补阙，只复用已有出处与已有 [n]；取材范围、登记格式与增量 Checker 核对以 [final-polish §0](final-polish.md#0-适用范围与红线) 红线 1 为准。材料、实际运行日志与在用信源都给不出解释时不补编，按 final-polish §5.3 记已知局限。修订或弃用既有类比须先同步 `lab/analogy.md` 登记表，再改正文全部引用处（一物一喻）；修文档不新增类比。

### 4.6 同构变式复测与出闸门禁 (Isomorphic Re-test Protocol)
- **严禁复测原题**：复测原题仅能验证短期记忆，无法验证真实理解；失败题换下一道同构变式备题，复述题照原题重跑（文档已变）。
- **每轮全新代理**：不复用上一轮上下文与作答；换上的备题沿用闭卷对照结论，新写的变式先闭卷对照。
- **轮次上限**：读懂、看会、学通每项至多 2 轮修文档复测，听知至多 1 轮；第 1 轮后同类缺陷未改善时，第 2 轮先回溯根因（常见为因果链缺环、白话没讲透或类比失配带偏），修订 lab 工作记录或 `lab/analogy.md` 后再改成稿；门禁标准不因停滞放松。
- **出闸**：四项全部通过即出闸；未过项按 [final-polish §5.3](final-polish.md#53-出闸判定) 有界闭合。单 Agent 运行时按角色隔离近似并标「非隔离」：失败照修，通过不作出闸依据、不阻塞交付，记入已知局限。
- **不作出闸证据**：cloze 填空、代理或判官的自评与偏好（含 §1.2 第 5 步的 1–5 分）、可读性公式与字数句长统计、代理 think-aloud 式的卡点自述（只用于定位）。

## 5. 沉淀笔记文档模板（Phase 4 · 入项目 docs）

```markdown
# <学习目标> 精读与通俗拆解
> [1] 主材料 IEEE 引用（所据版本 · 发布或更新日期）+ 来源链接（非最新版时一句交代最新版的相关变化；有勘误、撤稿或弃用时改用 `> [!IMPORTANT]` 醒目提示）
**一句话定位** / **SCQA 导读**（共识背景 → 痛点 → 本文回答的问题 → 各章分别解决什么、原型在哪）/ `> [!TIP]` **白话主线**（3–5 句直讲：问题 → 难点 → 思路 → 怎么验证）

## 1. 它要解决什么问题（通俗引入 + 设计规格表：规格|通俗版|对应机制）
```
