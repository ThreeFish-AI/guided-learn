# 讲授与沉淀模板（Phase 1–2 · 4）

Phase 1–2 的讲授在对话中交付；Phase 4 的两份沉淀文件按本文末尾的文档模板落盘。

## 一、全貌讲授结构（Phase 1）

按以下骨架输出，开头不加寒暄：

```
## 0. 一句话本质与类比
## 1. 最重要的部分（分层）
   | 层级 | 部分 | 回答的问题 | 性质 |  ← 表格
   Tier 1 地基+核心机制 / Tier 2 证据 / Tier 3 地图
## 2. 脉络：一条因果链
   观察 → 归因 → 设计规格 → 机制 → 证据闭环（文字流程图）
## 3. 基础 vs 焦点
   (a) 前置基础 (b) 最值得关注 N 点（按价值排序+理由） (c) 批判性边界
```

### 类比设计规范

- **总类比**选「外行有体感」的场景：师傅带徒弟 / 菜谱 vs 词典 / 导航 / 餐厅复盘 / 晴天修屋顶。
- 每个机制再配一个**局部类比**，且局部类比必须能映射到机制的每个组成部分
  （例：导航三连 = GPS 定位 ↔ Match、只看前方两路口 ↔ 2-hop 邻域、副驾导航员 ↔ guidance
  LLM、方向盘在你手里 ↔ 软注入——四个组成部分一个不缺）。
- 类比 1–3 句讲完；机制细节回到术语，不用类比硬凑。

### 因果链示例（Procedural Graph 实战）

```
观察：轨迹越长 agent 越失控（丢目标/乱序/重复）
  ↓ 归因
程序性一致性的责任被错误压在自由生成上
  ↓ 设计规格（四要求，全文总纲）
结构化 × 推理自由 × 响应进度 × 经验改进
  ↓ 机制
表示层（三元组+属性）→ 在线消费（定位+邻域+生成式软指导）
                     ↕ 两相解耦
                      离线进化（变异→验证门→拒绝记忆）
  ↓ 证据闭环
广度（N 基准 × M 模型）+ 深度（逐轮案例）+ 反直觉（从零进化 ≥ 专家）+ 设计自证（消融）
```

## 二、领域规律条目格式（Phase 2）

```
## 规律 N：<名称>（英文锚点）
**最简解释**：一句话，外行能懂。
**理论锚点**：IEEE 引用 1–3 条。
**解决什么问题**：没有它会坏在哪。
**演示**：用一手材料的实证数字现场演示 + 反面演示（它被违反时的实测代价）。
**类比**：一句话。
```

条目完成后声明正交分解：「N 条规律恰好覆盖 X / Y / Z 维度」——分解本身就是领域地图。

## 三、争议条目格式（Phase 2）

```
## 争议 N：<标题>——一句话点破张力
**通俗版**：生活化场景讲两派分歧（如：手册 vs 导师 / 真学习 vs 背题 / 小抄 vs 肌肉）。
**分歧为什么产生**：两派看到不同的失败模式（各自取样不同 → 都对）；
  指出分歧本质（如：连续谱选址问题 / 验证信号信度 / 成本结构经济学）。
**难以克服吗**：分层——资源问题 / 工程问题 / 本质难题；只对冲不可消除的要说死。
```

## 四、验收题与费曼测试设计（Phase 2 门禁）

- 题目设计：题型配比建议为「为什么这样设计」≥2 + 「与最近邻方法差在哪」≥1 + 「预测类（费曼测试）」≥1。
- 题目必须能从材料或原型实测中找到答案，不出模糊题。
- 答案要点写入沉淀笔记（用户先自答再对照）。
- 预测题模板：「给一个新任务 X，说出机制大概怎么表现 / 哪里会失效 / 第一步该观察什么」。

```

> IEEE 引用 + 来源链接
**一句话定位** / **总类比** / **怎么读这篇笔记**（三拍结构声明 + 原型位置）

## 1. 它要解决什么问题（通俗引入 + 设计规格表：规格|通俗版|对应机制）
## 2..k. 各核心机制（每节：类比 → 机制 → 原型实景[真实代码/日志引用]）
## k+1. 关键实证数字（| 实验 | 关键数字 | 一句话读法 |）
## k+2. 动手实验室（运行方式 + 机制→代码行号速查 + 破坏性实验实测）
## k+3. 批判性边界（5 条）
## k+4. 验收问答（答案要点，回指实验）
## k+5. 与本仓的关联（链接映射报告与相关设计文档）
## 参考（IEEE）
```

- 图两张：机制的「两相/多相」各一张，**archify 优先**（走项目资产管线四件套：.mmd 文本源 → archify HTML → 双主题 PNG → 暗色内嵌 + 索引登记）；无管线/无对应图型时降级内联 Mermaid。创作与验收纪律见 [diagram-assets.md](diagram-assets.md)。
- 笔记里引用的原型输出必须是**实际运行输出**，标注「实际运行日志」。
